# [프로젝트 1] 노코드 자동화 도구 비교 구현 보고서

## 1. 프로젝트 개요
- **프로젝트명**: SI 인력 매칭 이메일 자동 필터링 및 전달 파이프라인 구축
- **수행자**: SI 개발자 [작성자 이름]
- **작성일**: 2026년 7월 29일
- **구현 도구**: **Make** vs **n8n**

### 1.1 해결하고자 하는 문제 (Problem Statement)
- SI 개발자로 활동하면서 수많은 인력 협력업체/헤드헌터로부터 프로젝트 제안 이메일이 수시로 수신됨.
- 모든 메일을 직접 확인하고 선별하는 과정에서 작업 흐름이 끊기고 불필요한 공수가 발생함.
- 조건(단가, 개발 언어/프레임워크, 근무지, 경력 등)에 맞지 않는 메일을 미리 걸러내고, **핵심 조건에 부합하는 제안 메일만 보조/서브 이메일로 자동 재전송(Forwarding)**하는 자동화 루틴을 구축하고자 함.

---

## 2. 워크플로우 설계 (Trigger & Action)

### 2.1 로직 구조
```
[Trigger] 인력업체 수신 메일 감지 (Gmail / IMAP)
   │
   ▼
[Condition/Filter] 조건 검증
   ├── 조건 1: 제목/본문 내 필수 키워드 포함 (예: Java, Spring, React 등)
   ├── 조건 2: 희망 단가 이상 또는 특정 조건 포함 (예: 700만원 이상, 원격/상주)
   └── 조건 3: 제외 키워드 필터링 (예: 초급, 무관, 특정 비선호 지역)
   │
   ▼ (조건 충족 시)
[Action] 내 지정 서브 이메일로 포워딩/재발송
```

### 2.2 상세 모듈 세팅
- **Trigger**: `Gmail Watch Emails` 또는 `IMAP Email Trigger`
- **Filter / Switch**:
  - `Make`: Router 모듈 + Filter 조건 세팅
  - `n8n`: Switch 노드 또는 IF 노드 활용
- **Action**: `Gmail Send Email` / `SMTP Send Email` (지정된 보조 이메일 주소로 전송)

## 4. Make vs n8n 비교 분석

| 비교 항목 | Make (Integromat) | n8n |
| :--- | :--- | :--- |
| **운영 및 호스팅 형태** | SaaS 전용 (클라우드 기반) | 셀프 호스팅 (Docker/서버) 가능 + SaaS 제공 |
| **인터페이스 (UX/UI)** | 원형 모듈 기반의 시각적 캔버스 (매우 직관적) | 노드 연결 기반의 흐름도 형태 (개발자 친화적) |
| **조건 분기 (Filter/Switch)** | Router 선에 Filter 조건을 부여하는 방식 | IF / Switch 노드를 명확한 모듈로 배치하는 방식 |
| **데이터 가공 및 커스텀 코드** | Built-in 파싱 함수 사용 (자유도 보통) | JavaScript/Code 노드로 복잡한 로직 구현 가능 (자유도 높음) |
| **비용 및 요금제 체계** | 실행 건수(Operations) 제한 (무료 플랜 1,000 ops) | 셀프 호스팅 시 무료(무제한), 서버 유지비만 발생 |
| **SI 개발자 관점 총평** | 초기 설정이 빠르고 웹 UI가 깔끔함 | 코드 작성 및 자체 서버 구축이 자유로워 확장성에 유리 |

### 4.1 개발자 관점의 상세 비교
1. **데이터 파싱 및 커스텀 로직**:
   - `Make`는 이메일 본문에서 단가나 특정 정규표현식을 추출할 때 내장 함수 구문(`regexMatch`, `replace` 등)을 배워야 해서 약간의 번거로움이 있음.
   - `n8n`은 **Code 노드에서 순수 JavaScript/TypeScript**를 바로 사용할 수 있어, SI 개발자에게 데이터 가공의 친숙함과 작성 자유도가 훨씬 높음.
2. **비용 및 유지보수**:
   - `Make`는 메일 수신 감지 주기가 잦거나 수신량이 많을 경우 Operations 소모가 커짐.
   - `n8n`은 Docker 기반으로 자사/개인 서버에 올려두면 제한 없이 사용할 수 있어 개인 루틴 자동화 시 장기적으로 경제적임.

---

## 5. 결론 및 느낀 점

- **Make**는 쉽고 빠르게 시각적 필터링 구조를 짜고 결과를 테스트하기에 뛰어난 UX를 제공했습니다.
- **n8n**은 개발자 친화적인 환경과 셀프 호스팅의 이점, 그리고 코드를 통한 데이터 커스텀 가공이 용이하다는 강력한 장점이 있었습니다.
- SI 개발자로서 수많은 인력업체 메일 중 나에게 꼭 필요한 제안만 자동 추려보냄으로써 하루 최소 20~30분의 불필요한 이메일 스크리닝 시간을 절약할 수 있게 되었습니다.
